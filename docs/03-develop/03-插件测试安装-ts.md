# Obsidian 插件测试安装指南

## 1. 测试功能实现

在插件入口文件 `src/main.ts` 中添加简单的测试功能：

```typescript
async onload() {
  await this.loadSettings();

  // Add a test notification to verify plugin is loaded
  new Notice('CogniLink Assistant plugin loaded successfully! 🎉');

  // Other initialization code...
}
```

这个简单的通知可以直观地验证插件是否成功加载。

## 2. 测试环境设置

### 2.1 创建测试 vault

```bash
# 创建测试 vault 目录
mkdir -p ~/Documents/obsidian-test-vault

# 创建插件目录
mkdir -p ~/Documents/obsidian-test-vault/.obsidian/plugins/cognilink-assistant
```

### 2.2 安装插件

从项目根目录执行：
```bash
# 构建插件
npm run build

# 复制必要文件到插件目录
cp dist/main.js manifest.json styles.css ~/Documents/obsidian-test-vault/.obsidian/plugins/cognilink-assistant/
```

## 3. 测试步骤

1. 打开 Obsidian 应用
2. 选择 "打开其他保管库"（Open another vault）
3. 选择 `~/Documents/obsidian-test-vault` 目录
4. 启用插件：
   - 点击左下角设置图标（⚙️）
   - 选择 "社区插件"（Community plugins）
   - 在已安装插件列表中找到 "CogniLink Assistant"
   - 启用插件（打开开关）

## 4. 验证安装

成功安装后的验证点：
1. 插件加载通知：
   - 应该看到 "CogniLink Assistant plugin loaded successfully! 🎉"
2. 界面元素：
   - 左侧边栏出现消息图标
   - 点击图标可以打开聊天界面
3. 基本功能：
   - 设置面板可以正常打开
   - 命令面板中有插件命令

## 5. 开发模式（热重载）

对于开发过程中的实时测试，建议使用符号链接：

```bash
# 清理之前的文件
rm -rf ~/Documents/obsidian-test-vault/.obsidian/plugins/cognilink-assistant/*

# 创建符号链接
ln -s $(pwd)/dist/main.js ~/Documents/obsidian-test-vault/.obsidian/plugins/cognilink-assistant/main.js
ln -s $(pwd)/manifest.json ~/Documents/obsidian-test-vault/.obsidian/plugins/cognilink-assistant/manifest.json
ln -s $(pwd)/styles.css ~/Documents/obsidian-test-vault/.obsidian/plugins/cognilink-assistant/styles.css

# 启动开发模式
npm run dev
```

使用符号链接的好处：
- 自动同步更新：修改代码后自动重新构建
- 实时反馈：Obsidian 会自动重新加载插件
- 开发效率：无需手动复制文件

## 6. 故障排查

### 6.1 调试工具

打开 Obsidian 开发者控制台：
- Windows/Linux: `Ctrl + Shift + I`
- macOS: `Cmd + Option + I`

### 6.2 常见问题

1. 插件未显示：
   - 检查插件目录结构是否正确
   - 确认所有必要文件都已复制
   - 验证插件是否在设置中启用

2. 加载错误：
   - 检查控制台错误信息
   - 验证构建输出是否正确
   - 确认 manifest.json 配置正确

3. 功能异常：
   - 查看控制台日志
   - 检查 TypeScript 编译错误
   - 验证 API 调用是否正确

### 6.3 环境清理

需要重新开始时：
```bash
# 删除插件文件
rm -rf ~/Documents/obsidian-test-vault/.obsidian/plugins/cognilink-assistant/*

# 删除整个测试 vault（可选）
rm -rf ~/Documents/obsidian-test-vault
```

## 7. 最佳实践

1. 版本控制：
   - 保持 manifest.json 中的版本号更新
   - 遵循语义化版本规范

2. 测试策略：
   - 在开发初期使用简单的测试功能
   - 逐步添加更复杂的测试用例
   - 保持测试 vault 的整洁

3. 开发工作流：
   - 使用开发模式进行日常开发
   - 定期在新的测试 vault 中验证
   - 保持良好的错误处理和日志记录
