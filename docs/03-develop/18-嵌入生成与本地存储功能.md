
### 嵌入生成与本地存储功能已完成

#### 主要实现点
- **每个笔记的嵌入向量**会自动生成并存储在 `.obsidian/plugins/cognilink-assistant/embeddings.json`。
- 支持**增量更新**：只为新增或变更的笔记生成/更新嵌入，未变更的直接复用。
- 检索时优先用本地嵌入，未命中时自动补全。
- 存储内容包括：`path`、`embedding`、`updated`、`title`、`tags`。
- 所有存储操作均用 Obsidian 官方 API（`vault.adapter`），兼容 Obsidian 插件规范。
- 详细日志，便于调试和排查。

---

## 如何测试嵌入生成与本地存储

### 1. 触发嵌入生成
- 在插件主流程或命令中调用 `embeddingService.findRelevantNotes('测试主题')`。
- 或在已有的相关命令/入口（如“智能检索”）中输入任意主题，触发检索。

### 2. 检查本地存储
- 打开你的 vault 目录下 `.obsidian/plugins/cognilink-assistant/embeddings.json` 文件。
- 应能看到每个笔记的嵌入数据（JSON 格式），如：
  ```json
  {
    "docs/AI知识.md": {
      "path": "docs/AI知识.md",
      "embedding": [0.123, 0.456, ...],
      "updated": 1710000000,
      "title": "AI知识",
      "tags": ["#AI"]
    },
    ...
  }
  ```

### 3. 验证增量更新
- 修改或新增任意 Markdown 笔记。
- 再次触发 `findRelevantNotes`，对应笔记的 `embedding` 和 `updated` 字段会自动刷新。

### 4. 日志与异常
- 控制台会输出详细日志（如“Loaded embeddings index”、“Updating embeddings for X notes...”等）。
- 若有异常（如存储失败），会有 error 日志。

### 5. 单元测试建议
- 可在 `EmbeddingService.test.ts` 中 mock vault/adapter，验证 `findRelevantNotes` 能正确生成和持久化嵌入。
