完成标准

1. ESLint 和 Prettier 配置完成并能正常工作
2. Jest 测试框架配置完成并能运行测试
3. Git 工作流配置完成（包括 hooks、提交规范等）

## 开发环境配置详情

### ESLint 和 Prettier 配置

1. ESLint 配置 `.eslintrc.json`:
```json
{
  "root": true,
  "parser": "@typescript-eslint/parser",
  "plugins": ["@typescript-eslint", "prettier"],
  "extends": ["eslint:recommended", "plugin:@typescript-eslint/recommended", "prettier"],
  "env": {
    "browser": true,
    "es2021": true,
    "node": true
  },
  "parserOptions": {
    "ecmaVersion": 2021,
    "sourceType": "module",
    "project": "./tsconfig.json"
  },
  "rules": {
    "prettier/prettier": "error",
    "@typescript-eslint/explicit-function-return-type": "off",
    "@typescript-eslint/no-explicit-any": "warn",
    "@typescript-eslint/no-unused-vars": ["warn", { "argsIgnorePattern": "^_" }],
    "no-console": ["warn", { "allow": ["warn", "error"] }],
    "prefer-const": "warn",
    "no-var": "error"
  },
  "ignorePatterns": ["build/**/*", "dist/**/*", "node_modules/**/*"]
}
```

2. Prettier 配置 `.prettierrc`:
```json
{
  "semi": true,
  "tabWidth": 2,
  "printWidth": 100,
  "singleQuote": true,
  "trailingComma": "es5",
  "bracketSpacing": true,
  "arrowParens": "avoid",
  "endOfLine": "auto"
}
```

3. 代码规范要点：
   - 使用 TypeScript 严格模式
   - 使用 ES2021 特性
   - 强制使用 const/let，禁止 var
   - 限制 console 使用（仅允许 warn 和 error）
   - 统一代码格式（通过 Prettier）
   - 未使用变量警告（忽略下划线开头的参数）

### Jest 测试框架配置

1. 基础配置文件 `jest.config.js`:
```js
module.exports = {
  preset: 'ts-jest',
  testEnvironment: 'jsdom',
  moduleNameMapper: {
    '^obsidian$': '<rootDir>/__mocks__/obsidian.ts',
  },
  setupFilesAfterEnv: ['<rootDir>/jest.setup.js'],
  testMatch: ['**/__tests__/**/*.test.ts?(x)'],
  transform: {
    '^.+\\.tsx?$': ['ts-jest', {
      tsconfig: 'tsconfig.json',
    }],
  },
  moduleFileExtensions: ['ts', 'tsx', 'js', 'jsx', 'json', 'node'],
  collectCoverage: true,
  coverageDirectory: 'coverage',
  coverageReporters: ['text', 'lcov'],
}
```

2. Jest 设置文件 `jest.setup.js`:
```js
import '@testing-library/jest-dom';
```

3. Obsidian 模拟配置 `__mocks__/obsidian.ts`:
- 提供了基础的 Obsidian API 模拟实现
- 包含 `Notice`, `TFile`, `Vault`, `App` 等核心类的模拟

### 测试规范

1. 测试文件位置：
   - 测试文件放置在与源文件相同目录的 `__tests__` 文件夹下
   - 测试文件命名格式：`*.test.ts` 或 `*.test.tsx`

2. 测试文件结构：
   - 使用 `describe` 块组织测试套件
   - 使用 `it` 或 `test` 编写具体测试用例
   - 在 `beforeEach` 中进行测试准备工作

示例：
```typescript
describe('ServiceName', () => {
  let service;

  beforeEach(() => {
    service = new Service();
  });

  describe('methodName', () => {
    it('should do something', () => {
      // test implementation
    });
  });
});
```

### 运行测试

在项目根目录下运行：
```bash
npm test        # 运行所有测试
npm test:watch  # 以监听模式运行测试
```
