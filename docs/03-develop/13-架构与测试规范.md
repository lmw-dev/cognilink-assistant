# 架构与测试规范

## 技术实现方案

### 1. 目录结构与分层
- 推荐结构：
```
cognilink-assistant/
├── src/
│   ├── main.ts              # 插件入口
│   ├── services/            # 服务层（AI、数据处理等）
│   ├── components/          # UI 组件
│   ├── types/               # TypeScript 类型定义
│   ├── constants/           # 常量定义
│   ├── hooks/               # React Hooks
│   └── utils/               # 工具函数
├── dist/                    # 构建输出
├── __mocks__/               # Jest 模拟
├── tests/                   # 测试文件
├── docs/                    # 项目文档
├── styles.css               # 插件样式
├── manifest.json            # 插件清单
├── package.json             # 项目配置
└── tsconfig.json            # TypeScript 配置
```

### 2. 单元测试框架
- 使用 Jest/ts-jest，支持 TypeScript 测试。
- 测试文件与源文件同目录 `__tests__` 文件夹，命名 `*.test.ts(x)`。
- Mock Obsidian API，隔离外部依赖。

### 3. 代码风格与类型安全
- 启用 ESLint/Prettier 统一代码风格。
- TypeScript 严格模式，类型定义集中管理。

### 4. 关键服务/主流程测试
- 对主类、服务、UI 组件、命令注册等编写基础测试用例。
- 覆盖常见分支与异常处理。
