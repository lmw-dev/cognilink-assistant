## 1. RAG 构建是在哪里完成的？（嵌入的生成时机与流程）

### **核心原则**
- RAG 的“构建”本质是**为每篇笔记生成语义嵌入（embedding）向量**，并将这些向量与笔记元数据关联存储，便于后续检索。
- 构建过程**不是一次性全量操作**，而是**增量/懒加载**，即：只有在需要检索时，才会为尚未生成嵌入的笔记生成嵌入。

### **实现流程**
- **初次检索时**，遍历 Obsidian 库内所有 Markdown 文件：
  1. 读取每篇笔记内容。
  2. 调用 AIService（如 OpenAI/Anthropic）生成该笔记的嵌入向量。
  3. 将嵌入向量与笔记元数据（如标题、路径、标签等）一起存储到本地（见下文）。
- **后续检索时**，只需为新增加/修改的笔记生成嵌入，已生成的直接复用。
- **可选优化**：监听 Obsidian 的文件变更事件，自动为新增/修改的笔记生成/更新嵌入。

### **结论**
- **不是“加入到 Obsidian 就构建好”**，而是**在第一次检索或主动触发时**，为所有笔记生成嵌入，后续增量维护。

## 2. RAG 存储在哪里？（嵌入与索引的存储方案）

### **存储位置**
- **本地存储**，优先存放在 `.obsidian/plugins/cognilink-assistant/embeddings.json` 或类似的隐藏文件夹/文件中。
- 每条记录包含：笔记唯一标识（如路径）、嵌入向量、最后更新时间、元数据（如标题、标签等）。

### **存储格式**
- 推荐使用**JSON**或**二进制文件**（如 `.json`/`.bin`），便于序列化和快速读取。
- 示例结构（JSON）：
  ```json
  [
    {
      "path": "docs/AI知识.md",
      "title": "AI知识",
      "embedding": [0.123, 0.456, ...],
      "updated": 1710000000,
      "tags": ["#AI", "#知识"]
    },
    ...
  ]
  ```

### **安全与隐私**
- **仅本地存储**，不上传云端，保障用户隐私。
- 用户可在设置中手动清理/重建嵌入索引。

## 3. RAG 检索的范围是什么？（检索对象与可配置性）

### **默认范围**
- **所有 Obsidian 库内的 Markdown 文件**（即 `vault.getMarkdownFiles()` 返回的全部文件）。
- 不包括附件（如 PDF、图片），除非后续扩展支持。

### **可扩展/可配置**
- **支持范围过滤**，如：
  - 仅检索特定文件夹（如“知识库/”）。
  - 仅检索带特定标签的笔记（如 `#AI`）。
  - 仅检索最近 N 天内修改的笔记。
- 这些过滤条件可在设置界面或检索命令参数中配置。

### **实现建议**
- 在 `EmbeddingService` 和 `RAGService` 中，增加可选参数用于过滤检索范围。
- 例如：
  ```typescript
  findRelevantNotes(query: string, options?: { folder?: string; tag?: string; since?: Date; topK?: number; threshold?: number })
  ```

## 4. RAG 检索与内容整合主流程（详细时序图）

### **主流程分解**

1. **用户发起检索请求**（如输入主题/问题，点击“智能检索”按钮）。
2. **加载/生成嵌入索引**：
   - 检查本地是否已有嵌入索引。
   - 若无，则为所有目标笔记生成嵌入并存储。
   - 若有，则只为新增/变更笔记生成/更新嵌入。
3. **查询嵌入**：
   - 对用户输入（query）生成嵌入向量。
   - 计算 query 嵌入与所有笔记嵌入的相似度（如余弦相似度）。
   - 按相似度排序，筛选出前 N 条（可配置 topK/阈值）。
4. **内容去重、归类、摘要**：
   - 对检索到的内容做去重（如内容 hash、相似度聚类）。
   - 按标签/主题/文件夹等归类。
   - 可选：用 LLM 对每组内容做摘要。
5. **组装带归因的上下文**：
   - 每段内容后附来源编号/链接。
   - 生成“来源列表”。
6. **传递给 LLM 生成最终内容**：
   - 以“请基于以下资料，按主题分段整合并归纳总结，内容后附来源编号”作为 prompt。
   - LLM 输出带归因的整合内容。
7. **结果展示与交互**：
   - UI 分段展示整合内容，每段带归因编号/链接。
   - 底部附来源列表，支持点击跳转原笔记。
   - 支持一键插入到当前/新建笔记。

## 5. 伪代码示例

```typescript
// 1. 用户输入主题，发起检索
const query = "AI伦理";

// 2. 检索相关笔记
const relevantNotes = await embeddingService.findRelevantNotes(query, { topK: 8, threshold: 0.7 });

// 3. 去重、归类、摘要
const deduped = deduplicateNotes(relevantNotes);
const grouped = groupByTagOrTheme(deduped);
const summarized = await summarizeGroupsWithLLM(grouped, aiService);

// 4. 组装带归因上下文
const context = buildContextWithCitations(summarized);

// 5. 传递给 LLM 生成最终内容
const result = await aiService.sendMessage({
  role: 'user',
  content: `请基于以下资料，按主题分段整合并归纳总结，内容后附来源编号：\n${context}`,
  timestamp: Date.now(),
  id: Date.now().toString(),
});

// 6. 展示结果
showRAGResult(result, extractSources(summarized));
```

## 总结

- **RAG 构建**：在检索时为所有目标笔记生成嵌入，存储于本地插件目录，后续增量维护。
- **RAG 存储**：本地 `.obsidian/plugins/cognilink-assistant/embeddings.json`，包含笔记路径、嵌入、元数据。
- **RAG 检索范围**：默认全库 Markdown 文件，可配置文件夹/标签/时间等过滤条件。
- **主流程**：检索→去重归类摘要→组装带归因上下文→LLM生成→UI展示。

## 推荐的分步推进顺序

1. **嵌入生成与本地存储**  
   - 支持为所有笔记生成嵌入，并本地持久化。
   - 提供重建/增量更新机制。

2. **语义检索与排序**  
   - 支持输入 query，返回相关笔记（支持 topK、阈值参数）。
   - 支持关键词检索兜底。

3. **内容去重、归类、摘要**  
   - 对检索结果做去重、分组、可选摘要。

4. **归因机制**  
   - 检索结果与原笔记建立可追溯引用（编号、链接等）。

5. **内容整合与 LLM 生成**  
   - 组装带归因上下文，传递给 LLM，生成最终内容。

6. **UI/UX 展示与交互**  
   - 结果展示、归因交互、插入笔记等。

7. **参数配置与设置界面**  
   - 支持检索数量、阈值、整合方式等参数配置。

8. **单元测试与集成测试**  
   - 每步配套测试，保证质量。
