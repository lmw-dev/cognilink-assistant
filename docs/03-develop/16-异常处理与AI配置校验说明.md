# 异常处理与 AI 配置校验说明

## 1. 相关模块

- `SettingsManager`：负责插件设置的加载、保存、校验。
- `AIService`：负责 AI 消息处理、provider 实例化、异常分支抛出。

## 2. 主要异常场景

- **缺失 Anthropic API Key**
  - 当 provider 设为 `anthropic` 且 API key 为空时，抛出 `ConfigurationError: Anthropic API key is missing`。
- **不支持的 provider**
  - 当 provider 设为未实现的值时，抛出 `Error: Unsupported AI provider`。

## 3. Obsidian 插件内测试方法

### 3.1 测试缺失 Anthropic API Key

1. 打开插件设置页，将 AI provider 设为 `anthropic`。
2. 清空 API key 字段或输入无效值，保存设置。
3. 在插件界面触发 AI 功能（如发送消息）。
4. **预期结果**：弹窗或通知提示 `Anthropic API key is missing`，开发者工具 Console 有相关错误日志。

### 3.2 测试不支持的 provider

1. 手动编辑 `.obsidian/plugins/<plugin-id>/settings.json`，将 `ai.provider` 改为如 `foobar`。
2. 重启 Obsidian 或重新加载插件。
3. 触发 AI 功能。
4. **预期结果**：弹窗或通知提示 `Unsupported AI provider`，Console 有相关错误日志。

## 5. 代码实现要点

- 所有异常均通过 `throw new Error(...)` 或自定义 `ConfigurationError` 抛出，确保被主流程捕获。
- 建议在 UI 层对异常进行用户友好提示，并在 Console 输出详细日志，便于调试。
