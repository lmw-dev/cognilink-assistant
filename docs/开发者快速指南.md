# CogniLink Assistant 插件开发者指南

## 目录结构
- main.js           // 插件主入口，构建产物
- manifest.json     // 插件元数据
- styles.css        // 可选，插件样式
- src/              // 源码目录
- docs/             // 文档目录

## 本地开发与调试

### 1. 构建插件
```sh
npm run build
```

### 2. 安装到 Obsidian 插件目录
假设你的 Vault 路径为 `/Users/用户名/Documents/你的库名`：

```sh
rm -rf /Users/用户名/Documents/你的库名/.obsidian/plugins/cognilink-assistant
mkdir -p /Users/用户名/Documents/你的库名/.obsidian/plugins/cognilink-assistant
cp main.js manifest.json styles.css /Users/用户名/Documents/你的库名/.obsidian/plugins/cognilink-assistant/
```
（如无 styles.css 可省略）

### 3. 重启 Obsidian 或重新加载插件

### 4. 插件目录要求
插件目录下**必须**有：
- main.js
- manifest.json
- （可选）styles.css

### 5. 常见问题
- 插件不可见：请确认拷贝到当前 Vault 的 `.obsidian/plugins` 目录，重启 Obsidian。
- 版本号不对：请确认 manifest.json 已覆盖为最新，重启 Obsidian。

## 插件配置与安全最佳实践

### 1. API Key 输入框安全
- 建议将 API Key 输入框设置为 password 类型，避免明文回显。
- 当前实现为普通文本框，后续可升级为 password 类型。

### 2. API Key 加密存储
- 目前插件使用 Obsidian 的 this.saveData()/this.loadData() 机制，API Key 明文存储于本地。
- 如需更高安全性，可引入对称加密（如 crypto-js），对 API Key 加密存储，读取时解密。
- 加密密钥可基于本地环境生成，需权衡安全性与可用性。

### 3. 类型校验与 UI 提示
- 插件已实现类型安全的配置项定义与校验（TypeScript 类型、settingsValidator.ts）。
- 建议在 UI 层对 API Key、数值范围等进行实时校验，校验失败时给出用户提示。
- 当前实现为保存时校验，后续可增强为输入时校验。

### 4. 配置项存储与读取
- 所有配置项通过 SettingsManager/SettingsStorage 统一管理，持久化于 Obsidian 插件数据。
- 插件不会将 API Key 发送到非目标服务端点，也不会在日志、Notice、UI 明文显示。

### 5. 单元测试
- 配置相关逻辑已覆盖单元测试，建议每次功能变更后运行 `npm test` 验证。

### 6. Obsidian 验证方法
- 构建后将 main.js、manifest.json 拷贝到当前 Vault 的 .obsidian/plugins/cognilink-assistant 目录，重启 Obsidian。
- 在"设置"→"第三方插件"→"CogniLink Assistant"中，验证设置项是否可用，API Key 是否可保存与读取。

---

如需实现更高安全性的加密存储、UI 实时校验等，可参考本指南后续章节或联系维护者。
